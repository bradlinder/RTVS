ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

[ ] 3.1 MEDIA TRANSCODING & FORMAT CONVERSION ON EXPORT (AUDIO & VIDEO CODECS)
-------------------------------------------------------------------------------
Provides an integrated export option to convert segmented media files to common standard formats
(e.g., WAV -> MP3, MP3 -> WAV, AAC, FLAC, OGG, MP4, MKV) with support for standard audio and video codecs.

Implementation Details:
- Target Files: `processing.py`, `ui_layout.py`, and `RadioTVSegmenter.py`
- Format Selection UI:
  * Dropdown selector in the Export dialog / Export options menu:
    - Audio Formats: MP3 (libmp3lame, 128k/192k/320k), WAV (pcm_s16le, pcm_s24le), AAC (aac), FLAC (flac), OGG (libvorbis)
    - Video Formats: MP4 (H.264/AAC, H.265/HEVC), MKV (copy/transcode), WebM (VP9/Opus)
    - Pass-through option: "Original Source Format (No Re-encoding)"
- Engine & Pipeline:
  * Uses project-bundled FFmpeg binary via `processing.py` transcoding routines.
  * Preserves metadata tags (title, broadcast date, segment markers) across converted formats.
  * Fast multi-threaded batch transcoding during multi-segment export operations.

[ ] 3.2 UNIFIED CORE ASYNC RUNTIME PROVISIONER (RUNTIMEMANAGER ENGINE)
-----------------------------------------------------------------------
Consolidate separate background venv setup mechanisms (`processing.py`'s modal
QEventLoop dialog and `translation.py`'s QThread.moveToThread worker) into a single,
shared asynchronous engine inside `runtime_manager.py`.

Architectural Rules & Implementation Details:
- Target File: `runtime_manager.py` (Core)
- Decoupling Directive: Core modules MUST NOT import from `plugins/`. Plugins may import
  and consume core runtime helpers.
- Implementation:
  * `RuntimeSetupWorker(QObject)`: Universal background worker handling `ensure_environment()`.
  * `RuntimeManager.ensure_environment_async(feature_name, on_progress, on_finished, parent, **kwargs)`:
    Returns the managed `QThread` instance with automated lifecycle cleanup (`deleteLater`).
- Consumer Integration:
  * `processing.py` (Core: Whisper & Diarization): Taps into `ensure_environment_async()`
    with modal progress feedback, preserving synchronous flow without nested loop bugs.
  * `translation.py` (Optional Plugin): Taps into `ensure_environment_async()` with
    non-blocking background callbacks, automatically passing `plugin_dir` when installed.
- Benefits: Eliminates code duplication, prevents "bug drift" in pip/venv provisioning,
  standardizes progress/error reporting, and simplifies future plugin development.

[ ] 3.3 WHISPER HALLUCINATION & DEGENERATE LOOP SCRUBBER
---------------------------------------------------------
Whisper frequently enters repeating hallucination loops on audio with low SNR,
background music, or long silences, and emits standard ASR artifact phrases.

Implementation Details:
- Target File: `processing.py` (or new helper `transcript_cleaner.py`)
- Module Functions:
  * `collapse_repeating_ngrams(words, min_n=2, max_n=8)`:
    - Normalizes token keys: lowercase + strip non-alphanumeric punctuation.
    - Scans words left-to-right for repeating n-grams from max_n down to min_n.
    - Required repetitions before collapse: for n >= 4 phrases, requires 2+ repeats;
      for n < 4, requires 3+ repeats (prevents collapsing intentional "yes yes yes").
    - Greedily selects the match that removes the highest word volume.
  * `strip_hallucination_phrases(words)`:
    - Multi-token phrase blacklist matching:
      ["i'm sorry", "i am sorry", "thank you for watching", "thanks for watching",
       "please subscribe", "like and subscribe", "subscribe to my channel",
       "see you next time", "thanks for listening", "subtitles by",
       "subtitles by the amara.org community", "www.youtube.com"]
    - Drops only fully matched contiguous phrase sequences; preserves surrounding speech.
  * `trim_trailing_degenerate_tail(words, window_size=6, max_unique=2)`:
    - Whisper tail loops often end with dozens of "um" or "." tokens at audio end.
    - Scans backward from the final token. If the rolling window contains <= 2 distinct
      tokens and extends to the last word, trims the degenerate run if >= 6 words long.
  * `clean_transcript(words)`:
    - Sequentially executes collapse_repeating_ngrams -> strip_hallucination_phrases
      -> trim_trailing_degenerate_tail and re-indexes word timestamps/IDs.

[ ] 3.4 MULTI-LINGUAL FILLER WORD & DISFLUENCY DETECTION
----------------------------------------------------------
Identifies hesitations and filled pauses without altering genuine semantic vocabulary.

Implementation Details:
- Target File: `transcript_story.py` / `processing.py`
- Dictionary (`FILLER_WORDS` Set):
  * English: "um", "umm", "ummm", "uh", "uhh", "uhm", "erm", "er", "err", "ah", "ahh", "eh", "ehm"
  * Spanish: "em", "emm", "emmm", "eee"
  * German: "äh", "ähh", "ähhh", "ähm", "ähmm", "öh", "öhm", "ööhm"
  * French: "euh", "euuh", "euuuh", "euhm", "heu", "heum"
  * Portuguese: "hã", "hãhã", "ahn", "ahnn", "ãh", "ãhh", "ãhm", "éh", "éhh"
  * Chinese: "嗯", "嗯嗯", "呃", "额", "唔"
  * Shared Hums/Pushes: "hm", "hmm", "hmmm", "mh", "mhh", "mm", "mmm", "mhm", "mm-hmm", "uh-huh"
- Excluded words: Ambiguous natural speech tokens like "like", "so", "right", "you know"
  are excluded to prevent false positives in broadcast interviews.
- Disfluency handling: Support placeholder tags (e.g. `[pause]`, `...`, `[groan]`)
  produced by specialized ASR models.

[ ] 4.1 COCKOS REAPER PROJECT (.rpp) GENERATOR
-----------------------------------------------
Upgrades the simple EDL marker export to full multi-track Reaper project files.

Implementation Details:
- Target File: `project_export.py`
- RPP Structure:
  * Root `<REAPER_PROJECT 0.1 "7.0">` with sample rate (default 48000), BPM (120), tracks.
  * Track definition `<TRACK` with unique GUID (`{...}`).
  * Media items `<ITEM` for each kept segment range:
    - `POSITION <timeline_pos_seconds>`
    - `LENGTH <segment_length_seconds>`
    - `SOFFS <source_audio_offset_start_seconds>`
    - `FADEIN 1 0.005` / `FADEOUT 1 0.005` (5ms anti-click micro fades)
    - `NAME "<Segment Title or Media File Base>"`
    - `<SOURCE WAVE/MP3 FILE "<media_path>">`
- Supports both relative paths and absolute media paths for instant opening in Reaper.

[ ] 4.2 MAGIX SAMPLITUDE EDL (v1.5) EXPORT
-------------------------------------------
Sample-accurate text-based cut-list widely supported by legacy radio broadcast consoles
and DAW tools.

Implementation Details:
- Header: `Samplitude EDL File Format Version 1.5`
- Sample calculations: `samples = round(seconds * audio_sample_rate)`
- Columns: Source, Track, Play-In, Play-Out, Record-In, Record-Out, Volume, Pan, Fades, Name.

[ ] 4.3 VIDEO NLE INTERCHANGE (FCPXML & XMEML XML)
---------------------------------------------------
Generates sequence timelines for video newsrooms and multi-cam podcast edits.

Implementation Details:
- Supported Formats:
  * Apple Final Cut Pro XML (`.fcpxml` v1.9 / v1.10)
  * Adobe Premiere Pro / DaVinci Resolve Final Cut XML (`.xml` xmeml v4 / v5)
- Track Structure:
  * Video Track (V1) + Stereo Audio Tracks (A1, A2) mapped to source media.
  * Source in/out frame bounds and sequence timeline positions.
- Framerate Rational Time Base:
  * Supports 23.976 (24000/1001), 24 (24/1), 25 (25/1), 29.97 (30000/1001),
    30 (30/1), 50 (50/1), 59.94 (60000/1001), 60 (60/1) fps.
  * Time conversion helper: `seconds_to_rational(seconds, framerate)` to prevent drift.

[ ] 5.1 "TEXT-AS-TIMELINE" ROUGH-CUT EDITING ENGINE
----------------------------------------------------
Allows journalists to edit audio/video directly by striking through or deleting words
in the transcript UI.

Implementation Details:
- State Model:
  * Words have `deleted: bool` and `muted: bool` flags.
  * `get_word_cut_ranges(words, duration)`: groups contiguous deleted words into cut spans.
  * `merge_cut_ranges(ranges, duration, merge_gap=0.35)`: bridges micro gaps between cuts.
  * `get_keep_ranges(cuts, duration)`: inverts cut intervals into active playback/export clips.
- Word bar / timeline sync: Deleting text instantly recalculates segment boundaries
  and updates the duration counter in real time.

[ ] 5.2 SEAMLESS NON-DESTRUCTIVE PLAYBACK PREVIEW
--------------------------------------------------
- Custom audio playback handler in PySide6 / QMediaPlayer / sounddevice:
  * Plays only inside `keep_ranges`.
  * When playback cursor reaches a cut point, instantly seeks to the start of the next
    keep range with a 5ms linear volume crossfade to avoid popping artifacts.

[ ] 5.3 CTC WORD BOUNDARY REFINEMENT & FORCED ALIGNMENT
--------------------------------------------------------
- Whisper's token timestamps can have 50-150ms acoustic jitter.
- Optional secondary alignment pass using a lightweight Wav2Vec2 / MMS / CTC model:
  * Uses acoustic phone probabilities to snap word start/end times strictly to energy
    onsets and vowel/consonant transitions.
  * Result: Subtitle files (SRT/VTT) and audio slices are frame-accurate to 10ms.

[ ] 5.4 MEMORY-BOUNDED DIARIZATION & CHUNKED STREAMING
-------------------------------------------------------
- For long broadcast files (e.g. 2-6 hour council meetings or continuous broadcasts):
  * Segment audio into overlapping windows (`MAX_SEGMENT_S = 120s`).
  * Process Pyannote / speaker embeddings in bounded RAM/VRAM chunks.
  * Stitch speaker clusters across chunk boundaries using cosine similarity matching.
  * Prevents CUDA out-of-memory errors on consumer GPUs.
