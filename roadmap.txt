ROADMAP MAINTENANCE POLICY: N-1 SLIDING-WINDOW & STATUS TRACKING
--------------------------------------------------------------------------------
- The roadmap maintains a rolling window: it displays the current/immediate past
  release ($N-1$) for baseline context, followed by active upcoming development
  milestones ($N$, $N+1$).
- Status Notation Policy (Modeled after Social Digest):
  * All milestones and feature items are annotated with explicit progress indicators:
    - [x] Completed item / feature
    - [-] In-progress item / active development
    - [ ] Planned / not started item
  * When work commences on an item, mark it immediately as [-] [IN-PROGRESS].
  * Mark an item as [x] [COMPLETED] when implementation is finalized, upon user
    confirmation, or inferred when development transitions to another part of the roadmap.
- When a new version is built, its completed specifications are recorded, and any
  versions older than $N-1$ are pruned to keep the document focused and actionable.
- Whenever any code change, bug fix, packaging adjustment, or feature refinement is
  made during a release cycle, it MUST be recorded immediately in the current release
  section of roadmap.txt and CHANGELOG.md (even if it occurs after the initial version
  number bump).

1. PREVIOUS RELEASE: SHORTCUT CONFLICT RESOLUTION & COMMENT DUPLICATE PREVENTION (Completed in v3.1.6)
================================================================================

[x] 1.1 RESOLVE COMMENT SHORTCUT (CTRL+M) CONFLICT and RESTORE GLOBAL SHORTCUTS
-------------------------------------------------------------------------------
- Connected the global `add_comment_action` (`Ctrl+M`) to the MainWindow `add_comment_from_selection()` method instead of a non-existent transcript view method. This ensures that pressing `Ctrl+M` works globally across the application, whether the transcript view is focused or not, and eliminates silent shortcut collisions.

[x] 1.2 PREVENT DUPLICATE COMMENT CREATION ON TEXT SELECTION OVERLAPS
---------------------------------------------------------------------
- Restricted selection-based comments to exactly one primary segment target index in the comment editor dialog instead of copy-creating multiple independent comments when a selection boundary slightly overlaps adjacent segments. This ensures that clicking the comment button or using the shortcut adds exactly one comment per selection range.

2. CURRENT RELEASE: STABILITY, SECURITY, CHILD PROCESS TEARDOWN & ASYNC PROVISIONING (Planned for v3.2) [IN-PROGRESS]
================================================================================

[x] 2.1 OS-LEVEL CHILD PROCESS BINDING (WINDOWS JOB OBJECTS & POSIX PROCESS GROUPS)
------------------------------------------------------------------------------------
- Problem: If the application crashes, panics in native C code, or is terminated via Windows Task Manager, spawned worker processes (`python.exe`, `ffmpeg.exe`, translation/diarization workers) can leak and continue running in the background.
- Implementation:
  * Windows: Automatically create and bind the parent process and all spawned workers to an OS Job Object configured with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` via `ctypes.windll.kernel32`.
  * POSIX (macOS/Linux): Spawn background workers with new process groups (`preexec_fn=os.setsid` or `creationflags=os.setsid`) and register `atexit` / signal handlers to terminate the process group cleanly.
  * Register translation worker `QProcess` in `translation.py` directly into `register_process()`.

[x] 2.2 TRANSLATION PLUGIN SELF-CONTAINMENT & PURE CTRANSLATE2 ISOLATION
------------------------------------------------------------------------
- Problem: The translation worker retained a fallback to Hugging Face `transformers.AutoModelForSeq2SeqLM` and `torch`, forcing the isolated translation runtime to carry hundreds of megabytes of heavy PyTorch binaries and dependencies.
- Implementation:
  * Remove `torch` and `transformers` fallbacks from `plugins/translation/worker.py`.
  * Standardize model loading exclusively on quantized `ctranslate2.Translator` and `sentencepiece`.
  * Clean up `requirements-runtime.txt` in `plugins/translation/` to remove `torch` and reduce installation footprint, installation time, and DLL collision risks.

[x] 2.3 EMERGENCY UNHANDLED EXCEPTION PROJECT SNAPSHOT & CRASH RECOVERY
------------------------------------------------------------------------
- Problem: `sys.excepthook` writes a stack trace to log files, but does not preserve unsaved project data if an unhandled exception or native fault occurs.
- Implementation:
  * In `playback_preferences.py`, update `excepthook` to serialize the current project state into `<project_file>.crash_recovery.rtvs`.
  * On subsequent application launch, detect any existing `.crash_recovery.rtvs` files and prompt the user to recover unsaved work.

[-] 2.4 UNIFIED CORE ASYNC RUNTIME PROVISIONER (RUNTIMEMANAGER ENGINE)
-----------------------------------------------------------------------
- Consolidate separate background venv setup mechanisms (`processing.py`'s modal QEventLoop dialog and `translation.py`'s worker) into a single, shared asynchronous engine inside `runtime_manager.py`.
- Eliminates nested `QEventLoop.exec()` calls in `processing.py`, preventing event starvation, window freezes, and background worker leaks upon user cancellation.

[ ] 2.5 MEDIA TRANSCODING & FORMAT CONVERSION ON EXPORT (AUDIO & VIDEO CODECS)
-------------------------------------------------------------------------------
- Target Files: `processing.py`, `ui_layout.py`, and `RadioTVSegmenter.py`
- Integrated export option to convert segmented media files to common standard formats (MP3, WAV, AAC, FLAC, OGG, MP4, MKV, WebM) with bit-rate and codec controls.

[ ] 2.6 WHISPER HALLUCINATION & DEGENERATE LOOP SCRUBBER
---------------------------------------------------------
- Module Functions: `collapse_repeating_ngrams`, `strip_hallucination_phrases`, `trim_trailing_degenerate_tail`, `clean_transcript`.
- Strips repetitive degenerate loops and standard ASR artifact phrases from transcripts.

[ ] 2.7 MULTI-LINGUAL FILLER WORD & DISFLUENCY DETECTION
----------------------------------------------------------
- Cross-lingual dictionary detection for hesitations, fillers ("um", "uh", "äh", "euh"), and ASR sound placeholders.

[ ] 2.8 PIPELINE INTEGRATION & UI CONTROLS
-------------------------------------------
- Settings options for automated transcript cleaning and filler highlighting.
- Integration into `radio_tv_story_segmenter_worker.py` batch pipeline.
